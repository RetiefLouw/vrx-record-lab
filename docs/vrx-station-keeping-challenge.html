VRX Record Lab · challenge guide

Hold a vessel on station while the world pushes back.

VRX 2019 station keeping is a maritime autonomy benchmark: control a WAM-V surface vessel so its position and heading stay close to a fixed goal under simulated wind, waves, and environmental variation.

What the challenge asks

Station keeping is a closed-loop control problem. The goal is a pose—local X, local Y, and yaw—not a waypoint sequence. Your autonomy stack observes the vessel, estimates disturbance, produces a body-frame wrench or actuator command, and tries to keep the pose error small for the scored interval.

01

Observe

Read the vessel state and the published geographic goal. Convert the goal into a local reference and handle yaw wrap safely.

02

Control

Generate surge, sway, and yaw effort. The repository includes PID, a disturbance observer, constrained allocation, actuator limits, and a closest public-source UF MRAC port.

03

Hold

Remain close to the fixed pose while wind, waves, initial state, and scenario-specific parameters vary. Lower aggregate error wins.

Vehicle and frame

The benchmark uses the standard VRX WAM-V surface vessel. Pose error is interpreted in the local world frame; controller effort is ultimately applied in the body frame through the actuator stack.

Environment knobs

Public documentation describes bounded fog, ambient light, wind mean/variance/time/direction, and Pierson–Moskowitz waves. The exact hidden phase-3 configuration is unavailable.

One run, four states

Scoring is not active during setup. A run becomes meaningful only once the vehicle is released and the evaluator enters Running.

InitialSpawn and settle. Public world: 10 s.
ReadyGoal published; release. Public world: 10 s.
RunningTimer and score active. Public world: 300 s.
FinishedTask ends or times out.
Timing caveat. The 10 s + 10 s + 300 s timing is confirmed for the public station-keeping world. The private phase-3 world timing and wrapper behavior are not published.

Initial state

The Technical Guide says X, Y, and yaw are locked while transient Z, pitch, and roll can settle. The public launch path has a default local pose, but the guide also says starting pose varies between runs; the phase-3 override is unknown.

Goal state

The public world expresses the goal as latitude, longitude, and yaw, then converts it to a local pose. Exact phase-3 goal poses were not released.

How the score works—and why it is ambiguous

There are two public descriptions that must be kept side by side. The mismatch is part of the reproducibility problem; silently choosing one would overstate what is known.

published task description

RMS pose error

RMS = sqrt( Σ[ dx² + dy² + W·(Δheading)² ] / n )

The PDF defines an RMS pose error with a heading weight W. It does not publish the numeric weight, exact angle wrapping, or exact scorer sampling period.

public final-era code

Mean pose error

pose = sqrt(dx² + dy²)
      + 1 - | |goal_yaw - current_yaw| - π | / π
score = mean(pose)

The public station-keeping plugin accumulates this value on every world update. Its debug topic is named rms_error, although the assigned score is a mean.

Practical implication. A number produced by the local practice adapter is useful for engineering feedback, but it is not directly comparable to the historical UF result until evaluator revision, dependencies, hidden worlds, and scorer behavior are pinned.

Runs are aggregated, not cherry-picked

The official results page reports six station-keeping trials for the University of Florida. The published task score is the arithmetic mean of the six displayed run scores.

Task ranking

Teams are ranked low-to-high on the task score because this is a minimization problem.

Overall ranking

The overall total is the sum of task ranks. The lowest total wins.

UF reference

UF’s station-keeping task rank was 1; its official overall total was 25 and overall rank 5.

What a defensible rerun needs

A credible result is more than a low number. It needs an auditable experiment record that another person can run from a clean clone.

Record these inputs

  • Controller commit and configuration
  • Exact VRX, ROS, Gazebo, and OS package revisions
  • Container image digest and launch command
  • Every trial seed and environment parameter
  • Raw task info, run logs, and checksums

Verify these claims

  • Protected benchmark/scorer tree is unchanged
  • Development, verification, and evaluation seeds are disjoint
  • Aggregate arithmetic matches the raw trial values
  • Artifacts are present and SHA-256 manifests match
  • Claim language says “reproduced” only when direct comparability is demonstrated
