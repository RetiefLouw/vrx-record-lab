VRX Record Lab · evidence-led challenge explainer

Find a robotics score we can actually beat.

This project began with VRX station keeping, but the historical phase-3 record is not fully reproducible. We compared transparent public benchmarks and selected a smaller, auditable target for demonstrating low-cost LLM-guided iteration.

Current headline. The official LoRR 2024 Test Round reports 1,186 completed tasks. A frozen local replay of the archived Team RAPID implementation completed 1,318 tasks with zero planner, schedule, and entry-timeout errors. This is a verified local replay beat for one public instance—not an official leaderboard re-ranking or a generalization claim.

The benchmark decision in one view

A useful LLM demonstration needs a reported reference, a runnable evaluator, and iteration costs low enough to support several hypotheses. No single original VRX artifact satisfied all three.

historical / incomplete

VRX 2019 station keeping

Control a WAM-V surface vessel so position and heading remain near a goal under wind and waves. UF’s reported phase-3 mean is about 0.11, but generated worlds, exact scorer behavior, and runtime identity are missing.

near-leader fallback

BARN 2024 navigation

Run a Jackal through 50 public Gazebo worlds and score success/traversal time. The public LiCS-KI reference is 0.4762; our broad screen reached 0.46922 with 47/50 successes.

primary demonstration

LoRR 2024 Test Round

Coordinate 100 grid agents for 500 ticks while tasks are revealed. The archive exposes the exact input, evaluator lineage, winner source, and integer task-count field. Runs cost minutes on CPU.

Selection rule. Use the benchmark with the strongest combination of provenance, public evaluator, low-cost iteration, and visible margin. Use VRX for historical control research, BARN for embodied-navigation comparison, and LoRR for the main LLM-planning story.

What each challenge asks

These are different robotics problems, so their scores must never be compared numerically. The shared question is whether an autonomous controller can make good decisions under a fixed protocol.

VRX · hold a pose

Observe localization and heading, compute a body-frame wrench, allocate it to thrusters, and reject environmental disturbances. Lower mean pose error wins.

BARN · reach a goal

Use LiDAR and a local planner to traverse cluttered worlds. Each episode combines success with traversal time; the 50-world aggregate is an arithmetic mean.

LoRR · finish tasks

Assign newly revealed errands to many agents, plan collision-free paths, and keep replanning within a per-step time budget. Higher completed-task count wins.

Why LoRR is the best evidence target

  • The 2024 archive reports a concrete winner and task count.
  • The exact public instance is hashable and the v2.0.0 evaluator is open.
  • The score is legible: numTaskFinished, not a hidden composite.
  • One run is minutes, making hypothesis → test → audit practical.

What “winner” means here

The archive’s winner is the best-known submitted solution for a declared instance and simulation time. It is not automatically a portable executable or a guarantee of deterministic replay on another compiler/CPU.

How the selected LoRR run works

LoRR uses the MAPF-T action model: each agent moves forward, turns, or waits on a grid. Tasks are revealed over time, so the planner must balance throughput against computation time.

1 · RevealTasks and errands become available at release times.
2 · AssignThe scheduler matches tasks to agents using estimated completion cost.
3 · PlanLaCAM2/RHCR searches collision-free paths inside the time budget.
4 · ExecuteAgents follow actions for the next planning window; invalid actions are counted.
5 · ScoreAt 500 ticks, the evaluator writes numTaskFinished and error counters.

Score semantics

published score = numTaskFinished
comparison unit = one fixed instance
higher is better

The same field is emitted by the archived winner source and the v2.0.0 competition system. It is not the weighted pose formula used by VRX.

What can vary

Planner timeouts, compiler behavior, thread scheduling, and runtime details can change which tasks finish. We therefore record image digest, input hash, source commit, makespan, and all error counters.

What counts as innovation here?

The strongest story is not “an LLM magically beat the leaderboard.” It is that an LLM can find a measurable target, reconstruct its protocol, propose bounded experiments, reject attractive failures, and produce a reproducible evidence package.

01 research

Benchmark archaeology

We moved away from an unrecoverable VRX record after checking scorer, world, and runtime provenance instead of optimizing an incomparable number.

02 iteration

Cheap hypothesis loop

One change at a time—planner window, runtime control, source replay—made failures interpretable and kept experiments CPU-feasible.

03 evidence

Claim discipline

The local +132 result is reported with hashes and errors, while held-out failures remain visible. That is stronger evidence than a leaderboard-style headline alone.

Defensible wording

Say: “On the exact public LoRR Test Round instance, our frozen local replay completed 1,318 tasks versus the archived 1,186 reference.”

Do not say: “We won LoRR,” “we beat Team RAPID generally,” or “we set an official record.”

Next real innovation experiment

Implement one declared planner change aimed at reducing entry timeouts while preserving throughput. Evaluate it first on the Test Round for iteration, then on RANDOM-02/RANDOM-01 as held-out confirmation.
